# ComplianceRadar 设计理念与功能说明书

## 1. 工具定位

ComplianceRadar 是一个面向中国大陆监管信息场景的轻量级合规情报平台 POC。

它的目标不是做“全量监管数据库”，而是用最短路径帮助使用者回答三个问题：

1. 最近监管机关公开了哪些与融资租赁、商业保理相关的真实信息？
2. 这些信息释放了什么监管趋势和风险信号？
3. 从西门子财务租赁及商业保理业务合规的角度，应优先关注什么？

当前版本同时服务两类使用者：

- 人类使用者：通过独立 GUI 界面查看 Dashboard、事件清单、监管解读和导出结果
- AI 使用者：通过工具内配置的大模型，对抓取到的真实信息进行摘要、趋势判断和风险提示

## 2. 设计理念

### 2.1 真实优先

ComplianceRadar 的核心原则是“真实来源优先于漂亮展示”。

这意味着：

- 只展示真实抓取到的公告/新闻/处罚信息
- 每条信息必须保留对应的原始来源链接
- 不使用伪造标题、伪造主体、伪造来源页
- 抓取失败时返回错误，而不是自动补一个假的结果

### 2.2 管理层可读

系统输出不是为研究员写长篇笔记，而是为了让管理层、合规、法务和风控快速理解：

- 近期监管重点是什么
- 为什么这和融资租赁/保理业务有关
- 哪些控制点可能需要提早复核

因此，界面和输出都尽量压缩成“趋势 + 风险 + 行动提示”。

### 2.3 POC 先跑通闭环

当前阶段的目标不是一次性做复杂平台，而是先跑通一个完整链路：

1. 从 Source 抓取真实网页或 PDF
2. 定位与融资租赁/商业保理有关的信息
3. 抽取正文主体、发布时间、原始依据
4. 用已配置 LLM 做监管解读
5. 在 Dashboard 和 Regulatory Radar 中输出有价值的 early warning

## 3. 核心功能简介

## 3.1 Dashboard

Dashboard 是管理层入口。

它当前用于展示：

- 已抓取事件数量
- 重大事件数量
- 活跃信息源数量
- 主要监管主题
- 处罚原因分布
- 基于真实抓取事件形成的趋势时间窗
- 面向西门子财务租赁/商业保理的 early warning

其中的趋势时间窗不是写死的，而是根据当前工具实际抓到并纳入汇总的事件日期自动生成。

## 3.2 Event Library

Event Library 是事件清单。

它当前用于展示：

- 日期
- 监管机关
- 相关机构
- 分类
- 严重程度
- 原始主体
- Source Link

使用原则：

- 每条记录都应对应真实来源
- Source Link 点击后应跳到该条信息本身，而不是笼统栏目页
- 事件库只展示真实抓到且进入系统分析范围的信息

当前 POC 还支持：

- 本地时间区间筛选
- 手动刷新本地结果
- 一键触发信息源更新

## 3.3 Update All Sources

点击 `Update All Sources` 后，系统会弹出一个时间范围选择窗：

- Today
- Last 7 Days
- Last 30 Days

选择后会立即开始抓取与分析，弹窗自动关闭。

当前 POC 的抓取口径是：

- 每个 Source 每天最多抓取 3 条信息
- 重点是快速形成趋势样本，不做全量历史镜像

这样做的原因是：

- 降低 token 消耗
- 控制抓取量
- 更适合 Demo 与 POC 阶段快速稳定运行

## 3.4 Regulatory Radar

Regulatory Radar 是“监管解读工作区”。

它的定位不是聊天玩具，而是把当前抓到的监管事件转化为更直接的监管输出。

当前模块保留：

- 监管趋势概览
- 主要主题
- 观察窗口
- 使用当前模型生成的 Regulatory Output
- 面向业务的风险含义和建议动作

当前版本已经刻意删掉了多余的预设按钮和辅助卡片，目的是让界面更聚焦。

## 3.5 Source Center

Source Center 用于管理监管来源。

当前逻辑是：

- 可输入真实 URL 或完整中文机构名称新增来源
- 新增前会做基本校验
- 默认包含核心官方来源
- 可对来源做删除或检查最新信息

当前默认来源包括：

- 北京市地方金融管理局
- 上海市地方金融管理局
- 国家金融监督管理总局
- 中国人民银行

## 3.6 Model Gateway

Model Gateway 用于配置并使用云端大模型。

当前 POC 的基线模型是：

- Minimax China

当前支持：

- 配置 Base URL
- 配置 API Key
- 从兼容接口自动拉取可用模型清单
- 选择模型 ID
- 测试连接
- 保存配置

设计原则是：尽量不让使用者手工填写多余字段，而是优先让系统自动读取模型目录。

## 3.7 Export Reports

`Export Reports` 当前不是统一导出整个系统，而是按当前所在模块导出该模块信息。

当前支持导出：

- CSV
- HTML
- PDF

这使得演示时可以更清楚地区分：

- Dashboard 的管理层摘要
- Event Library 的事件清单
- Regulatory Radar 的监管输出
- Source Center 的来源状态

## 4. 当前运行原理

工具启动后，大致运行流程如下：

1. 启动本地 Flask API
2. 用桌面壳加载本地页面
3. 读取运行时状态、来源配置、模型配置
4. 使用者在 GUI 中触发更新或分析
5. 后端抓取真实网页/PDF
6. 清洗与抽取结构化字段
7. 调用当前配置的 LLM 生成风险解读
8. 将结果回写到 Dashboard / Event Library / Regulatory Radar / 导出文件

## 5. 当前 POC 边界

为了保证 Demo 可跑、可解释、可验证，当前版本有明确边界：

- 不做全国全量历史抓取
- 不保证所有来源都能 100% 稳定解析
- 以公开网页和公开 PDF 为主
- 每个来源每天最多取 3 条
- 更强调“真实样本 + 趋势解读”，而不是“数据规模”

## 6. 适合的演示口径

建议向使用者这样介绍当前工具：

> ComplianceRadar 不是传统台账工具，而是一个针对中国监管公开信息的轻量合规情报平台原型。它会从指定监管来源抓取真实信息，保留原始依据，并通过已配置的大模型把这些信息转换成管理层可理解的监管趋势和 early warning。

## 7. 当前已知限制

- 某些监管网站在网络、编码、反爬或页面结构变化时，可能导致抓取失败
- LLM 输出质量依赖当前模型可用性与配置状态
- POC 阶段导出的内容更偏演示与管理层摘要，不是正式法务意见书
- 一些旧测试或旧运行时缓存可能与最新界面口径不一致，需要以最新打包产物为准
